# Mastercard Developers
Mastercard Developers is a comprehensive API platform that provides issuers, acquirers, financial services companies, fintech, and developers with access to Mastercard products and services. The platform offers APIs for payments, fraud prevention, identity verification, open finance, loyalty management, digital commerce, and more. Developers can integrate these APIs to build modern financial experiences while leveraging Mastercard's security infrastructure and global reach.

### Authentication Facilitator
serviceId: authentication-facilitator
authType: OAuth1.0a
sourceUrl: /authentication-facilitator/documentation/index.md

Overview: The Authentication Facilitator API is a component of the Mastercard Authentication Service that enables MDES token requestors—such as digital wallets and commerce platforms—to authenticate cardholders using information maintained by the card issuer. It supports outbound web requests that notify issuers to deliver a Mastercard-generated authentication code to the cardholder. This code is then entered by the cardholder into the token requestor’s interface to complete authentication. The API is designed to work with any MDES token type and token requestor program, regardless of the card product or context of use, and is available only in approved business scenarios.

Why It Matters: The Authentication Facilitator API provides a secure and standardized way for token requestors to verify cardholder identity, enabling new digital use cases that require authentication beyond initial token provisioning. It helps issuers maintain control over authentication flows while supporting seamless consumer experiences. The service ensures privacy and security through mutually authenticated TLS and payload encryption, and is compliant with PCI DSS standards. By leveraging issuer-held cardholder data, the API supports flexible, scalable authentication across the MDES ecosystem.

### Automatic Billing Updater (ABU)
serviceId: automatic-billing-updater
authType: OAuth1.0a
sourceUrl: /automatic-billing-updater/documentation/index.md

Overview: Automatic Billing Updater (ABU) is one of the key security APIs on the Mastercard Developers Platform. Streamlining account lifestyle management for credential-on-file and recurring payment, ABU maintains a global repository of card account lifecycle events provided by issuers - such as new account creation, credential changes (ex: expiry updates or replacements), closures, brand flips, and portfolio upgrades. To obtain these lifecycle updates, ABU supports two integration models: a Push subscription model that delivers update notifications for accounts you subscribe to watch, and a Pull inquiry model for on‑demand checks via API or daily batch files.

Why it matters: Outdated credentials can cause a plethora of problems, both on the issuer and user side like declines, checkout friction, cart abandonment, and subscription disruptions.  ABU enables validation of current credentials before processing scheduled payments and supports subscribing new customer accounts for future change notifications. The push model is especially effective when future transaction timing is unpredictable, while the pull model works well as a fallback after a decline or as a proactive, periodic check to maintain account accuracy.

sourceUrl: /mastercard-buyer-payment-agent/documentation/index.md

Overview:  Mastercard Buyer Payment Agent enables Buyer Payment Agents (such as banks, procure-to-pay networks, and AP automation providers) to act on behalf of Buyers to submit and manage payment instructions to suppliers through Business Payment Service. The service supports card and account-to-account (A2A) payment initiation, status updates, and retrieval of payment instruction details, with global availability and certain use cases restricted by region. It also provides optional supplier verification (retrieve supplier details) and a structured linking process between buyers and suppliers to ensure the correct entities transact. Why It Matters: This API helps reduce friction in B2B transactions by standardizing payment processes, improving reconciliation, and enabling real-time data exchange. It supports use cases such as automated invoice payments, supplier onboarding, and payment preference enforcement. By connecting to Mastercard’s open-loop network, Buyer Payment Agents can reach a broader supplier base and offer more flexible payment options.

### Mastercard Processing Core
serviceId: mastercard-processing-core
authType: OAuth1.0a
sourceUrl: /mastercard-processing-core/documentation/index.md

Overview: Mastercard Processing Core provides APIs to manage card programs and transaction lifecycles within our Card Management System (CMS). We register transactions as documents and expose rich retrieval and management capabilities, including posting internal debit and credit transactions, charging ad‑hoc fees (predefined during onboarding), reversing transactions, and releasing blocked funds for pending transactions. The service also enables retrieving transactions and associated documents using multiple identifiers (such as ARN, RRN, SRN, and transactionId), alongside detailed amounts, currencies, posting statuses, and processing metadata.Beyond transactions, we support operational data management and controls. You can retrieve account contracts for a client (with pagination), obtain contract tree structure summaries, and fetch usage limit details stored in the CMS. Configuration uses dictionaries to validate and transform values between the API and CMS, and to enforce data formats (for example, character sets and masks), while classifiers and parameters can be set or retrieved at client or contract level.

serviceId: open-finance-us
authType: OpenBanking
sourceUrl: /open-finance-us/documentation/index.md

Overview: Open Finance US is our suite of API-based services that enables secure, consumer-permissioned access to financial data and decisioning to power payments, money management, and lending use cases. Core capabilities include account aggregation with tiered data access, real-time or cached account balances, account owner verification with optional identity insights, transaction data enrichment, and bank account validation via microdeposits (Account Validation Assistant). We also provide predictive risk tools such as Payment Success Indicator for assessing NSF risk and Consumer Foresight for spend insights, benchmarking, and forecasting, alongside lending analytics and reports.

The service helps reduce payment risk and improve approvals by combining real-time balance checks with predictive NSF scoring and explanatory attributes (PSI), and by validating routing/account details when users can’t or won’t link accounts (AVA). For lending, we evaluate account balances and cash flows, generate Payment History and Statement reports, and support small and medium business credit assessment. For personalization and PFM, Consumer Foresight delivers category-level historical trends, peer benchmarks, and future spend forecasts. Operationally, Client Hub surfaces financial institution connection health and invoice history, while Connect customization and UX guidance help deliver accessible, user-friendly consent and linking experiences. Note: some capabilities are premium or billable (for example, Get Available Balance live/cached, Consumer Foresight, and Statement Report), and PSI is for non-FCRA use cases with an FCRA variant available.

### Token Requestor Identifier API
serviceId: token-requestor-identifier-api
authType: OAuth1.0a
sourceUrl: /token-requestor-identifier-api/documentation/index.md

Overview: The Token Requestor Identifier (TRID) API is part of Mastercard’s Digital Enablement Service (MDES) and enables On-Behalf-Of Token Requestors (OBOTRs)—typically Payment Service Providers (PSPs)—to onboard and manage token requestors such as merchants or commerce platforms. The API allows OBOTRs to register token requestors in batches, update their details, and receive a unique Token Requestor Identifier (TRID) for each onboarded entity. This TRID is then used to tokenize card credentials via the MDES Tokenize API. The service supports streamlined onboarding, duplicate TRID detection, and eliminates manual errors through automation.Why It Matters: Token Requestor Identifier API helps PSPs operating in the On-Behalf-Of model manage token requestors across diverse merchant portfolios efficiently. It simplifies integration by offering a single interface for both creation and updates, reduces operational overhead, and ensures accurate token domain mapping. By enabling fast and secure onboarding, the API helps PSPs accelerate time to market for tokenized payment solutions and maintain consistency across digital commerce environments.

It can be used to initiate bulk search, check status, and retrieve results.

### Transaction Notifications
serviceId: transaction-notifications
authType: OAuth1.0a
sourceUrl: /transaction-notifications/documentation/index.md

Overview: Transaction Notifications is a powerful API that delivers real-time transaction data , including both authorization and clearing events, to applications with enrolled cardholders, once appropriate consent is obtained. It supports both bulk enrollment (via issuers, corporate admins, or fintech partners) and individual enrollment, where cardholders authenticate directly with the application.Once a card is enrolled, applications receive timely, context-rich notifications for eligible card activity, enabling dynamic engagement and personalized experiences.Why Use Transaction Notifications?Whether you're building a budgeting app, fraud alert system, loyalty platform, or personalized rewards experience, Transaction Notifications gives you the ability to react instantly to cardholder activity. This enables:Real-time engagement: Trigger contextual messages, offers, or insights the moment a transaction occurs.Enhanced user trust: Provide transparency and security through instant alerts and confirmations.Smarter personalization: Use transaction data to tailor experiences, recommendations, and financial insights.Developer-Friendly Features Transaction Notifications is built with developers in mind, offering:Hosted Web UI: For applications that prefer not to handle PCI data directly, we offer a secure, Mastercard-hosted web interface for cardholder enrollment and consent capture. Reliable delivery: Automatic retries for failed webhooks over a 24-hour window, with progressive backoff. Resilience: Undelivered notifications are stored for up to 7 days and can be retrieved via a dedicated API.Flexibility: Support for multiple webhook endpoints and customizable payloads to meet data separation and minimization requirements.

Keywords: Real-time transaction data, Cardholder purchase notifications, Expense management automation, Credit card transaction notification, Network transaction data, Personalized financial experiences
